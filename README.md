# Forgot to Reset Skills

죽으면 현재 회차의 진행은 초기화되지만, 보상으로 획득한 스킬은 잃지 않는다는 발상에서 시작한 2D 로그라이크 액션 게임입니다.

플레이어는 반복되는 회귀를 통해 영구 스킬을 확보하고 스킬트리를 확장하며, 일반 전투와 보스전을 순차적으로 돌파합니다.

## 프로젝트 개요

- **장르**: 2D 로그라이크 액션 / 보스 러시
- **핵심 콘셉트**: 사망하면 스테이지 진행은 처음으로 돌아가지만 획득한 영구 스킬은 유지됩니다.
- **플레이 흐름**: 일반 전투 → 보스전 → 스킬 보상 → 다음 스테이지 또는 회귀
- **개발 목적**: Unity의 컴포넌트 구조를 활용해 전투, 스킬트리, 저장, 보스 이벤트처럼 서로 연결된 시스템을 직접 설계하고 완성하는 포트폴리오 프로젝트입니다.

## 주요 기능

### 회귀와 영구 성장

- 플레이어가 사망하면 현재 회차의 스테이지, 레벨, 임시 스킬과 아이템을 초기화합니다.
- 보스 보상으로 획득한 영구 스킬과 스킬트리 진행 상태는 저장하여 다음 회차에도 유지합니다.
- 새 게임과 이어하기에서 동일한 저장 규칙이 적용되도록 런 데이터와 영구 진행 데이터를 분리했습니다.

### 데이터 기반 스킬 및 스킬트리

- `SkillData`, `SkillTreeData`, `SkillTreeNodeData`를 ScriptableObject로 구성했습니다.
- 스킬 데이터 하나를 플레이어, 지원 캐릭터와 같은 여러 전투 주체가 공용으로 사용할 수 있도록 설계했습니다.
- 선행 노드, 트리 가시성, 해금 가능 상태와 실제 획득 상태를 구분했습니다.
- 액티브 스킬 장착, 쿨타임, 버프 효과, 근접 공격과 투사체 스킬을 하나의 사용 흐름에서 처리합니다.

### 전투와 데미지 계산

- 공격력, 방어력, 치명타, 속성, 랭크와 버프를 분리된 계산 요소로 구성했습니다.
- 근접 공격은 애니메이션 이벤트 시점에 히트박스를 생성해 실제 공격 모션과 판정 시점을 맞췄습니다.
- 화염 검격과 보스 투사체는 생성 주체의 방향과 데이터를 전달받아 이동 및 데미지를 처리합니다.
- 동일한 공격 판정이 한 대상을 여러 번 타격하지 않도록 피격 대상을 기록합니다.

### 보스전 시스템

- 전투 시작 시 제한 벽을 활성화하고 보스 등장 연출 후 전투를 시작합니다.
- 체력 구간에 따른 광폭화, 잡몹 소환, 원거리 공격과 돌진 공격을 구성했습니다.
- 보스 사망 시 보상 지급, 클리어 UI와 포탈 활성화까지 이어지는 흐름을 구현했습니다.
- 이미 획득한 영구 보상을 다시 지급할 수는 있지만, 중복 보상 UI는 표시하지 않도록 보상 상태를 먼저 검사합니다.
- 라스트 보스전은 지원 캐릭터 이벤트와 엔딩 진행 흐름을 별도로 연결했습니다.

### 지원 캐릭터 이벤트

- 보스전 도중 지정된 위치에 지원 캐릭터와 말풍선 UI가 함께 등장합니다.
- 등장 직후 살아 있는 적을 탐색하고, 사거리까지 이동한 뒤 스킬 데이터를 사용해 공격합니다.
- 보스뿐 아니라 전투 중 계속 소환되는 일반 적도 새로운 대상으로 인식합니다.
- 라스트 보스전에서는 지원 캐릭터의 공격에 따라 보스의 어그로가 전환될 수 있도록 구성했습니다.

### 플레이어 애니메이션과 이동

- 기존 캐릭터 프리팹 의존성을 제거하고 신규 플레이어 프리팹과 애니메이터를 연결했습니다.
- Idle, Run, Attack, Hit, Die 애니메이션과 공격 판정 이벤트를 구성했습니다.
- 점프 시작, 상승, 체공, 하강, 착지를 수직 속도와 접지 상태에 따라 전환합니다.
- 2단 점프 시 상승 애니메이션에 다시 진입하도록 처리했습니다.
- 공격 중에는 이동과 방향 전환을 잠가 공격 모션과 AttackPoint가 어긋나지 않게 했습니다.
- 경사면 끝에서 Rigidbody2D의 상승 운동량 때문에 캐릭터가 튀어 오르는 문제를 별도의 지면 고정 로직으로 보완했습니다.

### UI 및 게임 진행

- 스킬트리 탭, 트리 선택, 노드 상태와 스킬 장착 UI를 구성했습니다.
- 보스 보상, 클리어, 패배, 지원 대사와 엔딩 UI를 게임 진행 상태에 맞춰 표시합니다.
- 보스전 종료 후 포탈을 통해 다음 진행 또는 엔딩으로 연결합니다.

## 기술 스택

- **Engine**: Unity 6
- **Language**: C#
- **Platform**: PC
- **Input**: Unity Input System
- **Data**: ScriptableObject, JSON Save Data
- **Physics**: Rigidbody2D, Collider2D, Composite Collider 2D
- **UI**: Unity UI, TextMesh Pro

## 어려웠던 점과 해결 과정

### 1. 영구 스킬 보상과 스킬트리 UI 상태 불일치

- **문제점**: 보스 보상으로 스킬 데이터는 지급됐지만 해당 스킬 노드는 `해금 완료`가 아닌 `해금 가능` 상태로 표시됐습니다. 회귀 전후에 보상을 받는 시점과 저장 시점도 달라져, 특정 종료 순서에서만 영구 스킬이 남는 문제가 있었습니다.
- **원인**: 보상 시스템은 스킬 획득 여부를 기준으로 동작했고, 스킬트리 UI는 노드 ID와 선행 조건을 기준으로 상태를 계산했습니다. 동일한 성장을 서로 다른 식별자와 저장 경로에서 관리하고 있었습니다.
- **해결과정**: 보상 데이터가 `SkillData`를 직접 전달하도록 정리하고, 스킬 데이터로 해당 노드를 찾은 뒤 영구 획득과 노드 해금을 하나의 흐름에서 처리했습니다. 저장은 여러 하위 메서드에서 반복하지 않고 최종 변경이 완료된 시점에 수행하도록 책임을 명확히 했습니다.
- **결과**: 보상 지급, 실제 사용 가능 스킬, 스킬트리 노드 표시와 회귀 후 저장 상태가 동일하게 유지됩니다.

### 2. 최초 스킬트리 노드 클릭이 반응하지 않는 문제

- **문제점**: 게임을 처음 시작해 `탭 → 트리 선택 → 노드 클릭` 순서로 진입하면 어떤 노드를 눌러도 첫 클릭은 반응하지 않고 두 번째 클릭부터 정상 작동했습니다. UI를 닫았다가 다시 열면 재현되지 않았습니다.
- **원인**: 최초 UI 활성화 시 선택 상태와 노드 데이터 갱신 순서가 맞지 않아 첫 입력이 실질적인 노드 선택이 아니라 초기 상태 설정에 사용되고 있었습니다.
- **해결과정**: UI를 처음 열 때 현재 탭과 트리를 먼저 확정하고 노드 목록과 선택 상태를 즉시 갱신하도록 초기화 순서를 수정했습니다.
- **결과**: 첫 진입에서도 노드를 한 번 클릭해 정상적으로 선택하고 해금할 수 있게 됐습니다.

### 3. 보스 및 소환 적의 공격 판정 구조

- **문제점**: 적의 공격 상태와 애니메이션은 실행됐지만 실제 공격 판정 프리팹이 생성되지 않았습니다. 돌진형 적은 이동 전체에 데미지를 넣으면 선딜과 공격 모션이 맞지 않는 문제도 있었습니다.
- **해결과정**: 플레이어의 공격 히트박스 구조를 적 전용으로 분리하고 `EnemyAttackHitBox`를 구현했습니다. 공격 애니메이션의 유효 구간 또는 이동 컨트롤러의 공격 활성 이벤트에서만 프리팹을 생성하고, EnemyData의 공격력을 전달했습니다.
- **결과**: 일반 공격, 보스 공격과 햄스터 돌진이 실제 모션의 타격 구간에서만 데미지를 가하도록 연결됐습니다.

### 4. 프리팹 교체 후 방향 처리의 기준 불일치

- **문제점**: 신규 플레이어는 `FacingRoot.localScale.x`로 방향을 전환하지만 기존 투사체는 플레이어 루트의 Y 회전을 검사했습니다. 그 결과 AttackPoint는 정상적으로 좌우 이동해도 화염 검격은 항상 한쪽으로만 발사됐습니다.
- **해결과정**: 화면 방향을 판단하는 기준을 `FacingRoot`의 실제 스케일로 통일했습니다. 플레이어의 Visual과 AttackPoint를 같은 FacingRoot 아래에 두어 반전 시 함께 이동하게 했습니다.
- **결과**: 근접 공격 위치, 캐릭터 이미지와 투사체 이동 방향이 모두 일치합니다.

### 5. 점프 애니메이션과 물리 상태 동기화

- **문제점**: 점프를 하나의 재생 애니메이션으로 처리하면 체공 시간과 낙하 시점, 2단 점프를 실제 Rigidbody2D 속도에 맞추기 어려웠습니다. 경사면에서는 점프하지 않아도 마지막 지점에서 위로 튀어 오르는 현상이 발생했습니다.
- **해결과정**: 점프 애니메이션을 시작, 상승, 체공, 하강, 착지 상태로 분리하고 `VerticalSpeed`와 `IsGrounded`를 Animator 파라미터로 전달했습니다. 점프 직후에는 짧은 시간 동안 접지 판정을 무시하고, 일반 지상 이동 중에는 허용되지 않은 상승 속도를 제한하는 `GroundStickController`를 추가했습니다.
- **결과**: 점프 높이와 체공 시간이 달라져도 애니메이션이 물리 상태를 따라가며, 2단 점프와 경사면 이동도 자연스럽게 동작합니다.

### 6. 지원 캐릭터의 타깃 탐색과 보스전 종료 조건

- **문제점**: 지원 캐릭터가 보스에게 접근하지 않거나, 큰 보스의 중심점만 기준으로 거리를 계산해 서로 붙어 있어도 공격하지 않는 문제가 있었습니다. 처음 지정한 보스만 추적하면 이후 소환되는 잡몹을 공격하지 못했습니다.
- **해결과정**: 대상 Transform 중심이 아니라 Collider2D의 가장 가까운 지점까지의 거리를 사용해 공격 사거리를 계산했습니다. 살아 있는 Enemy 대상을 반복 탐색하고, 현재 대상이 사라지면 새로 소환된 적을 다시 선택하도록 구성했습니다. 전투 종료는 순간적으로 대상이 없다는 조건이 아니라 보스전 컨트롤러의 실제 종료 흐름에서 결정하도록 역할을 분리했습니다.
- **결과**: 크기가 다른 보스와 일반 적 모두에게 정상적으로 접근하고 공격하며, 소환 적이 추가되어도 전투를 계속합니다.

## 알게 된 점과 배운 점

- **데이터와 UI는 같은 상태를 바라봐야 한다**: 실제 스킬 획득, 노드 해금과 화면 표시를 따로 관리하면 작은 순서 차이가 버그로 이어집니다. 하나의 원본 상태를 기준으로 UI를 갱신하는 것이 중요했습니다.
- **자동 저장은 편의 기능이면서 책임의 경계다**: 모든 하위 메서드가 자동 저장하면 중복 호출과 불완전한 상태 저장이 발생할 수 있습니다. 복합 작업에서는 최종 조정자가 한 번 저장하도록 선택할 수 있어야 했습니다.
- **Transform 방향 기준은 프로젝트 전체에서 통일해야 한다**: 회전, `SpriteRenderer.flipX`, 음수 스케일을 혼합하면 투사체, 자식 오브젝트와 애니메이션의 방향이 쉽게 어긋납니다.
- **애니메이션은 표현이고 게임 상태는 코드가 관리해야 한다**: 공격 유효 시점은 Animation Event로 맞추되, 공격 가능 여부와 이동 잠금은 코드 상태로 관리했습니다. 점프 역시 Animator의 Exit Time보다 실제 수직 속도와 접지 상태를 우선했습니다.
- **거리 계산에는 오브젝트 크기가 포함되어야 한다**: 중심점 간 거리만 사용하면 대형 보스와의 근접 판정이 부정확합니다. Collider의 ClosestPoint를 사용하면서 시각적 크기와 전투 사거리의 차이를 해결했습니다.
- **프리팹 공용화와 인스턴스 전용 설정을 구분해야 한다**: 공용 보스 프리팹을 수정하면 모든 스테이지에 영향을 줍니다. 라스트 보스 전용 연출처럼 한 장면에만 필요한 요소는 씬 인스턴스 Override 또는 별도 프리팹 변형으로 관리해야 합니다.
- **작은 시스템도 전체 플레이 흐름에서 검증해야 한다**: 개별 기능 테스트뿐 아니라 새 게임, 이어하기, 사망, 회귀, 보상 중복과 엔딩까지 연결한 회귀 테스트가 필요하다는 점을 배웠습니다.

## 현재 상태와 향후 개선 사항

- 3개 보스 스테이지와 라스트 보스 이후 엔딩 흐름까지 연결했습니다.
- 신규 플레이어와 지원 캐릭터의 기본 전투 및 애니메이션을 구성했습니다.
- 임시 전투 사운드 연결을 시작했으며, 효과음과 BGM의 정식 교체 및 볼륨 믹싱이 남아 있습니다.
- 라스트 보스 전용 아우라와 추가 시각 효과를 보완하고 있습니다.
- 향후에는 3번째 보스 패턴 개선, 지원 이벤트 연출 강화와 전체 밸런스 조정을 진행할 예정입니다.

## 프로젝트 실행

1. Unity 6에서 프로젝트를 엽니다.
2. `Assets/Scenes/Title` 씬을 실행합니다.
3. 새 게임 또는 이어하기를 선택해 플레이합니다.
